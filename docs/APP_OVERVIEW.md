# RVault — полное описание приложения (для анализа)

Состояние: версия 3.9.0 (versionCode 74), ветка `claude/android-contact-database-app-jl3lik`, репозиторий `Rykovtt/Ttst`.
Документ описывает **что есть в коде на сегодня**, что измерено и что нет. Цифры качества — с телефона пользователя (Samsung Galaxy S24 Ultra), прислал сам пользователь; на устройстве мы (разработчик-ИИ) ничего не запускали.

---

## 1. Что это

**RVault** — личный зашифрованный офлайн-архив людей для Android (Kotlin, Jetpack Compose). По сути CRM для одного человека (мастер, тату-художник, консультант и т.п.): карточки людей, записи на приём, рассылки, напоминания, голосовые заметки — плюс **голосовой ассистент «Ноа»** (пользователь переименовал его в «Санта»), который управляет и приложением, и телефоном: звонки, сообщения, музыка/YouTube, маршруты, будильники, запись голосовых заметок.

- Пакет кода `com.kartoteka.app`, applicationId `com.rykov.rvault`, minSdk 26, targetSdk 35, только `arm64-v8a`.
- Интерфейс на трёх языках: русский, украинский, английский (`assets/i18n.tsv`, ~1360 строк: ключ = русский текст).
- Язык сообщений людям настраивается отдельно (в т.ч. по человеку).
- Приложение без облака: `INTERNET` нужен только для скачивания моделей, карты (OpenStreetMap) и поиска ссылок на YouTube.
- Код: ~26 500 строк Kotlin (main), 41 файл тестов, **317 юнит-тестов**, CI: GitHub Actions собирает APK на каждый push (артефакт `RVault-apk`).
- Размер APK 26,8 МБ (3.9.0).

## 3. Функциональность (кратко, подробный список — `README.md`)

- **Карточка человека**: ФИО, фото-галерея, телефоны/контакты (E.164), день рождения, близость, группы, связи (муж/жена/дети…), произвольные поля, хроника, голосовые заметки, места на карте.
- **Календарь записей**: запись на дату/время/услугу/место, пересечения, подтверждения/напоминания/перенос/отмена с сообщением человеку, шаблоны текстов по услугам.
- **Рассылки**: WhatsApp/Telegram по очереди, SMS автоматически, выбор получателей по критериям, плейсхолдеры `{имя}`, `{приветствие}` на трёх языках.
- **Карта**, **статистика**, **импорт из контактов телефона**, **дни рождения** (лента + уведомления), маскировка значка и названия.
- **Авто-отправка** (в RVault осталась только связь `AutoSendLink` с отдельным приложением RVServices; сама служба — в модуле `autosend`, пакет `com.rykov.autosend`, проверяет подпись вызывающего).
- **Голосовые заметки**: запись в зашифрованный PCM, расшифровка на устройстве (Android 13+), поиск по ним.

## 4. Безопасность и приватность

- БД: SQLCipher AES-256, ключ в Android Keystore. Фото и голос: AES-256 (`FileVault`), не попадают в галерею.
- PIN (хэш PBKDF2) + биометрия, пауза после 5 ошибок, автоблокировка, `FLAG_SECURE`, скрытие в «недавних», «встряхнуть — закрыть», защищённый буфер обмена.
- Бэкап: файл `.krtk`, шифрованный паролем (PBKDF2 + AES-256); автобэкап в выбранную папку; облачный бэкап Google выключен.
- Ассистент: всё распознавание речи (Vosk для имени, системное для команд) и вся языковая модель — **на устройстве**. Журнал непонятых фраз — опциональный, локальный, имена маскируются; пересылает сам пользователь.
- Разрешения, существенные для ассистента: `RECORD_AUDIO`, `FOREGROUND_SERVICE(_MICROPHONE)`, `SYSTEM_ALERT_WINDOW` (сфера поверх экрана), `WAKE_LOCK`, `SET_ALARM`, `KILL_BACKGROUND_PROCESSES`, доступ к уведомлениям (`NotificationListenerService`: управление плеером, чтение/ответ в мессенджерах).

## 5. Ассистент «Ноа/Санта» — главная часть и главный риск

### 5.1 Что умеет

Команды голосом/текстом (ru/uk/en, свободная речь): записать/перенести/отменить человека, позвонить, написать (WhatsApp/Telegram/Viber/SMS), прочитать входящие и ответить, заметка/напоминание, открыть карточку/раздел/приложение/закрыть приложение, музыка и YouTube (включить трек/плейлист/«понравившиеся»/видео с канала/сериал, пауза/дальше/shuffle), громкость в процентах («на 40», «громче на 20», «на максимум»; при максимуме — сообщает), маршрут, будильник/таймер, фонарик, блокировка, калькулятор/конвертер/время, поиск в интернете, CRM-вопросы («кто завтра в 15:00», «сколько записей на неделю», «когда окна», «у кого ДР»), **запись голосовой заметки о человеке** («открой голосовые заметки об Илье и начни запись», стоп голосом «стоп запись» или кнопкой в шторке).

Вызов голосом: фоновая служба `WakeService` (foreground, тип microphone) слушает **имя** оффлайн-моделью Vosk (`vosk-model-small-ru-0.22`, ~45 МБ) по узкой грамматике; двойная проверка свободным распознаванием (в режиме «Строго»); три режима «слышимости при музыке» (Строго/Обычно/Чутко), журнал слуха (`WakeDiag`) для диагностики.

### 5.2 Конвейер разбора команды

```
речь → текст
  1. Правила: NoaParser.parse (1400 строк): морфология ru/uk, цепочки «и/потом», время/даты (NoaDateTime), «suspicious»-вето → Unknown
  2. Если Unknown или подозрительно (имя не из книжки и т.п.) → языковая модель (NoaInterpreter + LlmBrain)
       - динамические few-shot примеры (NoaExamples, ~2,5 тыс. «фраза → JSON», поиск по основам слов + триграммам)
       - контекст из данных (NoaContext: список людей, планы на сегодня/завтра)
       - ответ модели — JSON {"actions":[…]}; Lenient-парсер; реестр действий (≈40 действий) с алиасами; слой починки
         (repairStep: подмена перепутанных действий, выброс выдуманных людей/услуг, имя из фразы вместо переспроса,
         латиница↔кириллица в именах, транслит Oleg→Олег)
  3. Если и модель молчит/пусто → запасной разбор по ближайшему примеру библиотеки (только простые действия, всегда с подтверждением)
  4. Исполнение (Noa.kt): Reply.Say / Confirm / Do(действие после речи) / Navigate; команды от модели, которые пишут людям, звонят,
     меняют данные или лезут в другие приложения, исполняются только после «да» (NoaTrust.needsConfirm + NoaDescribe).
```

Правила идут первыми намеренно: модель — только для того, что правила не поняли.

### 5.3 Языковая модель

- Сейчас **единственная модель — Gemma 4 E2B** (`gemma-4-E2B-it.litertlm`, 2,59 ГБ, Apache-2.0), движок **LiteRT-LM** на процессоре; скачивается один раз из настроек. Работает в отдельном процессе `:brain` (`BrainService`, протокол через `Messenger`), чтобы нехватка памяти не убивала приложение.
- Генерация: `ConversationConfig(SamplerConfig(topK=1, topP=1.0, temperature=0.1, seed=1))`, новый разговор на каждый запрос (без памяти), шаблон диалога применяет сам движок. Окно 2048 токенов, запрос в среднем ~410 токенов (оценка), ответ — компактный JSON.
- История моделей: Qwen2.5-1.5B и Phi-4 mini 3.8B (MediaPipe `.task`) → убраны в 3.9.0. Phi-4: 9–13 с на ответ. Gemma 4: ~2,5 с.
- Подключение LiteRT-LM — «на проверенных данных» только в виде отчётов пользователя; на S24 Ultra процессор, GPU/NPU не используются.
- Файл модели обязан иметь расширение `.litertlm` (иначе движок ищет zip и падает: «Unable to open zip archive» — была реальная ошибка в 3.8.0).

### 5.4 Инструменты качества (встроены в приложение)

- «Проверка ИИ» (настройки ассистента): гонит **весь конвейер** (правила → модель → библиотека) на размеченных фразах `golden_free.tsv` (289 фраз, разметка вручную: подпись команды, напр. `Call`, `Seq(Message,GoHome)`); короткая — 100 равномерно выбранных, полная — все 289 + диагностика «эталона по правилам» (`golden_phrases.txt`, 143). Отчёт: «верно», «уверенно неверно», кто отвечал (правила/модель/библиотека), время, ошибки с сырым ответом модели.
- Журнал непонятых фраз (`NoaFeedbackLog`, по желанию), журнал сбоев (`CrashLog`), журнал слуха (`WakeDiag`).
- Юнит-тесты фиксируют каждую найденную ошибку (воспроизведённые ответы моделей из отчётов: `NoaReport*Test`, `NoaScreenshotCasesTest`, `NoaRescueTest`, `NoaFreeParseTest` и др.).

## 6. Измеренное качество (по отчётам с телефона)

Набор — 100 фраз «весь конвейер» (одни и те же 100 из 289 при каждом запуске):

| Версия / модель | Команда верна | Уверенно неверно | Ответ получен | Время ответа (средн./95%) |
|---|---|---|---|---|
| 3.7.2 · Phi-4 mini | 66% | 15% | 91% | 9,3 с / 17,5 с |
| 3.7.3 · Phi-4 mini | 74% | 6% | 88% | 8,7 с / 17,0 с |
| 3.8.1 · Gemma 4 E2B | 80% | 11% | 96% | 2,6 с / 5,1 с |
| 3.8.2 · Gemma 4 E2B | **90%** | **5%** | 100% | 2,5 с / 5,2 с |

Без модели (только правила) на полном наборе из 289: ~28% верно, ~1% уверенно неверно, остальное — «не понял» (передаётся модели).

**Важная оговорка (переобучение под тест):** ошибки из этого же набора чинились кодом в нескольких раундах, так что 90% завышены. Честная оценка на новых фразах пока **не получена**. План: накопить фразы через журнал непонятых.

Остающиеся известные ошибки: передача данных другому человеку («отправь Ане карточку Ильи»), «вкажи на Машу» (Select), «вбий у пошук погода у Львові», «скільки в мене клієнтів завтра покажи розклад», условные команды («если завтра есть запись — отправь подтверждение») не поддержаны вообще; «Олег» → модель путает с «Олексій» (если Олега нет в книге, переспрос правильный).

## 7. Известные ограничения и риски (для анализа)

1. **Нет проверки на новых фразах.** Главный пробел измерения (см. выше).
2. **Движок LiteRT-LM на устройстве проверен только отчётами пользователя**: один телефон, процессор. Память ~1,7 ГБ + модель 2,6 ГБ на диске; на слабых телефонах не проверялось. Для устаревших моделей (Phi/Qwen) есть авто-удаление файлов при обновлении.
3. **Wake-word при громкой музыке/видео**: Vosk с узкой грамматикой; при музыке распознавание тонет. Введены три режима и журнал, но улучшение на устройстве не подтверждено. Есть ложные срабатывания от рилсов в режиме «Чутко».
4. **Запись голосовой заметки**: остановка по голосу — свободное распознавание Vosk по фразе «стоп запись» (с минимумом 3 с и подтверждением двумя чтениями); исправлена ошибка, когда ассистент сам произносил «стоп запись» и останавливал запись. Не подтверждено устройством после исправления.
5. **Скорость**: ~2,5 с в среднем, но 95-й перцентиль ~5 с; первая загрузка модели несколько секунд.
6. **Управление чужими приложениями** (YouTube/YouTube Music/Spotify/мессенджеры) — через интенты, ссылки (`watch?list=LM` для «Понравившиеся» и поиск ссылок на YouTube страницей результатов), медиасессии и ответ через RemoteInput уведомления. Запуск конкретного видео/плейлиста зависит от разметки YouTube — хрупко. Автоматических нажатий в чужих приложениях в RVault нет; отдельный модуль `autosend` (RVServices) — отдельная ответственность владельца проекта.
7. **Данные в модели**: в запрос попадают имена людей и планы на день (только локально; сеть не используется).
8. Расшифровка голосовых заметок зависит от системного офлайн-распознавания (Android 13+, нужны скачанные языки).
9. Тесты — в основном юнит; **UI и работа на устройстве автоматизированно не тестируются** (нет эмулятора с моделью в окружении разработки).
10. `README.md` частично устарел (упоминает MediaPipe/Gemma ~1,3 ГБ; верно: LiteRT-LM + Gemma 4 E2B ~2,6 ГБ).

## 8. Что можно спросить у анализирующего ИИ

- Как честно измерить точность ассистента без утечки тестового набора в разработку (hold-out, ротация фраз, синтетика)?
- Стоит ли дообучать узкого специалиста (FunctionGemma 270M / Qwen 0.5–1.5B с LoRA) на схеме действий RVault; как перевести его в формат LiteRT-LM для Android; ожидаемый выигрыш против Gemma 4 E2B с few-shot?
- Как уменьшить долю «уверенно неверных» (сейчас 5% на подогнанном наборе): калибровка уверенности, обязательные подтверждения, второй проход модели?
- Архитектура wake-word при музыке: альтернативы Vosk (openWakeWord/Porcupine/свой keyword-spotter), аппаратная AEC, дакинг громкости при зове.
- Рекомендации по тест-инфраструктуре для ассистента на устройстве (инструментальные тесты, устройство-ферма, воспроизводимость).
- Риски архитектуры: правила 1400+1200 строк регулярных/словарных проверок на трёх языках — как сдерживать рост сложности.
